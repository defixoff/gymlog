# GymLog 🏋️

Автономное PWA-приложение «дневник тренировок» в ультра-лаконичном стиле.
Светло-оранжевая тема + стильная тёмная, плавные CSS-анимации, mobile-first.
На ПК — боковое меню и двухколоночная главная.
**Без зависимостей на фронтенде**: один HTML + один CSS + один JS.

## Что нового в v2

- **Анимации везде**: сплэш-экран со штангой, живой фон-сферы, листание вкладок,
  скользящая пилюля навигации, count-up цифр, рисующиеся сглаженные графики,
  столбики с пружиной, ripple на кнопках, круговая смена темы (View Transitions),
  bottom-sheet с физической пружиной и жестами, тосты с прогрессом,
  **конфетти при рекорде и завершении тренировки** (canvas-confetti),
  Motion One подключён локально (`vendor/`) — работает офлайн.
- **Таймер отдыха** — автостарт после каждого подхода, ±15 с, вибрация по окончании,
  длительность настраивается в профиле.
- **Детектор рекордов (PR)** прямо во время подхода, рекорды считаются по 1ПМ (Эпли),
  упражнения с собственным весом учитываются.
- **Стрик** дней подряд, **трекер недели**, подсказка «прошлый раз: 3×80×8»,
  таймер длительности тренировки, тренд ↑/↓ в аналитике, объём по неделям.
- Перетаскивание упражнений в расписании, переименование, экспорт/импорт JSON.
- Гостевой режим доступен и при живом сервере («Продолжить без аккаунта»).

### Исправленные баги
- сервер отдавал `.env.local`, базу и исходники бэкенда как статику → белый список;
- данные предыдущего пользователя попадали в новый аккаунт → кэш привязан к логину;
- Service Worker кэшировал `/api/*` → офлайн-состояние затирало серверное;
- неудачный PUT терялся → повтор, индикатор синхронизации, досылка при `online`;
- сравнение хешей паролей не timing-safe; добавлен rate-limit, лимит размера state,
  чистка просроченных сессий; минимальный пароль — 6 символов;
- дата тренировки бралась в UTC (после 03:00 по Минску уезжала на вчера);
- несколько записей веса за день ломали график; `orientation: portrait` ломал десктоп-PWA;
- проект не запускался на Node < 22 → фолбэк-драйвер `backend/db-json.js`.

## Возможности

- **Аккаунты** — регистрация и вход по логину/паролю; у каждого пользователя
  свои тренировки в базе данных.
- **Профиль** — имя, возраст, вес (с графиком динамики веса).
- **Конструктор расписания** — тренировочные дни и списки упражнений.
- **Экран тренировки** — тренировку можно назвать, день выбирается уже внутри
  сессии; упражнение записывается одной строкой: подходы × вес × повторения.
  Тренировки в истории можно переименовывать и удалять.
- **Главный экран** — аналитика: SVG-график объёма, тоннаж, счётчики
  и плашка «Максимальные рекорды» (лучший вес + оценка 1RM по формуле Эпли).
- **PWA** — `manifest.json` + `sw.js`: установка на домашний экран и работа офлайн.

## Запуск локально

Рекомендуется Node.js ≥ 22 (встроенный SQLite). На Node 18–20 сервер автоматически
переключится на JSON-файл `data/gymlog.json`.

**Вариант 1 — SQLite (ноль зависимостей):**

```bash
node server.js
# → http://localhost:3000, база: data/gymlog.db
```

**Вариант 2 — PostgreSQL (например, Neon):** создайте `.env.local` в корне
(файл в `.gitignore`, в git не попадает):

```
DATABASE_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
```

затем `npm install` (ставится только `pg`) и `node server.js` — сервер сам
выберет PostgreSQL. Проверка соединения: `node test-db.js`.

База создаётся автоматически (таблицы `users`, `sessions`, `states`).
Зарегистрируйте пользователя — и все тренировки хранятся в базе.

Если открыть приложение без сервера (любой статический хостинг, `npx serve .`,
даже `file://`), оно стартует в **гостевом режиме** на localStorage — ничего
не ругается, всё работает, но без аккаунтов.

## Архитектура данных

Один общий API-слой, два драйвера БД:

```
backend/core.js        — логика API (auth + состояние), не знает про СУБД
backend/db-sqlite.js   — драйвер SQLite (локально, node:sqlite)
backend/db-postgres.js — драйвер PostgreSQL (локально через .env.local и на Vercel)
server.js              — локальный сервер: статика + /api/* (Postgres или SQLite)
api/[...api].js        — Vercel serverless: те же маршруты на PostgreSQL
```

Маршруты API: `POST /api/register`, `POST /api/login`, `POST /api/logout`,
`GET /api/me`, `GET /api/state`, `PUT /api/state`, `GET /api/ping`.
Пароли хешируются scrypt + соль, сессии — токены на 30 дней.
Тесты: `node test-api.js` (смоук-тест API при запущенном `server.js`),
`node test-db.js` (проверка соединения с PostgreSQL).

Фронтенд при старте делает `GET /api/ping`:
- сервер есть → экран входа, данные пользователя в базе;
- сервера нет → гостевой режим на localStorage.

## Чеклист перед деплоем

- [ ] В Neon/Vercel сменён пароль БД (старый `.env.local` попадал в архив).
- [ ] `DATABASE_URL` добавлен в Vercel → Settings → Environment Variables (Production + Preview).
- [ ] `assetlinks.json`: `package_name` и `sha256_cert_fingerprints` соответствуют вашему TWA-приложению
      (иначе Android покажет адресную строку).
- [ ] После деплоя открыть `https://<домен>/api/ping` → `{"ok":true}` и `/.env.local` → 404.
- [ ] При обновлении фронтенда менять `CACHE` в `sw.js` — пользователи получат тост «Доступна новая версия».

## Деплой на Vercel (PostgreSQL)

1. Закоммитьте проект и загрузите в репозиторий (GitHub/GitLab):

   ```bash
   git add .
   git commit -m "GymLog"
   git push
   ```

2. В Vercel: **Add New → Project** → импорт репозитория.
   Framework Preset: **Other**, Build Command — пустой,
   Output Directory — пустой (подтянется из `vercel.json`).

3. Добавьте Postgres: **Storage → Create → Postgres** (или Neon/Supabase).
   Переменная `DATABASE_URL` привяжется к проекту автоматически
   (иначе добавьте вручную: Settings → Environment Variables).

4. Deploy. Таблицы (`users`, `sessions`, `states`) создаются автоматически
   при первом запросе к API.

Статика раздаётся как есть, `/api/*` работает как serverless-функции.
Локальная SQLite-база и `.env.local` на деплой не попадают (см. `.gitignore`).
